# Stakeholder Analysis — Mobile Deck-Building Card Game

## Stakeholders

| Stakeholder | Role | Needs | Expectations |
|---|---|---|---|
| Players | Primary users of the game | Easy-to-understand gameplay, deck customization, enjoyable matches | Game should be fun, responsive, balanced, and easy to learn |
| Development Team | Designs and builds the game | Clear requirements, manageable scope, development tools, communication | Project can realistically be completed within the course timeline |
| Instructor | Evaluates the project | Clear documentation and evidence that requirements are being followed | Team meets assignment requirements and demonstrates progress |
| Playtesters | Test the game during development | A working version of the game and a way to report problems | Bugs and gameplay problems they identify are considered by the team |

## How These Needs Shape the Product

1. **Easy to learn** — rules and tutorials are designed for first-time players (Players, Playtesters).
2. **Deck customization and strategy** — players can build decks and experiment with card combinations (Players).
3.**Documented progress** — stakeholders, vision, requirements, and feedback are recorded in this repository (Instructor, Development Team).
